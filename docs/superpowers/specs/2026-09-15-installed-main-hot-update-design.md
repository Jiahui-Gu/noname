# 安装版跟随 main 的热更新设计

## 目标

让 Windows Electron 安装版在每次启动时检查 `Jiahui-Gu/noname` 的 `main` 分支，并在不打断当前对局的前提下更新游戏内容：

- 启动时静默检查并下载可热更新文件。
- 当前对局继续使用已经加载的代码。
- 回到安全的非对局状态后自动刷新游戏窗口，使新内容生效。
- Electron 外壳、依赖或构建配置变化不在线覆盖，改为提示安装新版。
- 更新失败时继续使用上一份完整版本，不留下半更新状态。

“无需重启”指不退出 Electron 进程；由于 JavaScript 模块、技能定义和运行中对象已经载入内存，当前对局内无刷新替换不属于支持范围。

## 方案选择

采用 GitHub commit/tree 增量同步：

1. 客户端读取本地已应用提交 SHA。
2. 查询 GitHub API 获取 `main` 最新提交及递归文件树。
3. 比较本地清单与远端树，下载变化的 `apps/core` 文件。
4. 在暂存目录完成下载和 Git blob SHA 校验。
5. 对完整暂存结果执行切换，并记录新 SHA 和清单。

相比每次下载完整仓库快照，该方案下载量更小。相比要求 CI 为每次提交发布更新包，该方案无需先搭建发布流水线。清单格式与下载器保持独立，以便未来切换到 CI 签名更新包。

## 更新边界

### 可热更新

构建产物中由 `apps/core` 生成并位于 Electron `resources/app` 游戏根目录下的内容，包括：

- 游戏 JavaScript、CSS、HTML 与配置数据。
- 武将、卡牌、模式和扩展兼容代码。
- 游戏图片、音频等静态资源。

### 必须升级安装包

以下源路径发生变化时，不尝试在线覆盖，并提示用户安装新版：

- `apps/electron/**`
- `packages/**`
- 根目录依赖与构建文件，如 `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`
- 任何无法可靠映射到安装版游戏目录的文件

客户端通过 GitHub compare API 检测从已应用 SHA 到远端 SHA 的路径变化并分类。如果 compare 结果被截断、基线提交不可比较或分类不确定，采用保守策略：不应用热更新，提示安装新版。

## 组件

### Electron 主进程更新服务

主进程负责所有网络和文件系统操作，渲染进程不直接决定写入路径。

- `UpdateService`：检查版本、获取 compare/tree、分类更新。
- `UpdateDownloader`：限制并发下载，写入 staging，计算并校验 Git blob SHA。
- `UpdateStore`：持久化当前 SHA、文件清单、待应用状态和错误信息。
- `UpdateInstaller`：验证完整性后切换文件；启动时恢复或清理中断状态。

更新状态保存在 `Home/UserData` 下，不随游戏文件覆盖。暂存内容保存在同一磁盘上的专用目录，以便使用原子重命名。

### 主进程与渲染进程通信

使用最小 IPC 接口：

- 主进程发送更新状态：检查中、下载中、等待安全切换、需要安装包、失败。
- 渲染进程报告是否处于可刷新状态。
- 主进程仅在“下载已完成”且“渲染进程安全”时触发窗口 reload。

IPC 参数使用固定结构并校验；渲染进程不能传入任意文件路径或 URL。

### 安全切换判定

游戏启动后默认为安全。进入实际对局时标记为不安全；对局结束并回到开始/大厅界面时重新标记为安全。

如果可靠的对局生命周期钩子暂时无法覆盖所有模式，则首版降级为“下载完成后展示应用按钮，按钮仅在开始界面可用”，不得猜测状态并在对局中强制刷新。

## 数据流

1. Electron 创建主窗口后异步启动检查，不阻塞首屏。
2. 获取 `main` HEAD SHA；与本地 SHA 相同则结束。
3. compare 本地 SHA 与远端 SHA：
   - 存在外壳变更：记录“需要安装包”，不覆盖任何文件。
   - 仅有 `apps/core` 变更：继续获取树并生成目标清单。
4. 下载新增或变化文件到 staging；删除项只记录，不立即操作。
5. 校验每个文件的大小和 Git blob SHA，并验证目标路径位于允许根目录。
6. 构造完整下一版本目录或可回滚事务，验证入口文件存在。
7. 原子切换成功后写入本地 SHA/清单；失败则保留旧版本并报告错误。
8. 若渲染进程安全，刷新窗口；否则等待对局结束。

## 一致性与回滚

不能直接边下载边覆盖正在使用的目录，否则网络失败会产生混合版本。

首选实现是版本目录加“当前版本指针”：内置版本作为只读基线，下载版本存入 `Home/Updates/versions/<sha>`，本地 HTTP 服务从当前指针解析文件。完成校验后原子更新指针，窗口刷新后使用新版本。这样无需改写安装目录，也避开 Windows 安装目录权限问题。

更新目录应只保存当前版本、上一版本和正在下载版本。若新版本刷新后未能完成启动握手，主进程恢复上一指针并再次刷新；连续失败后禁用该 SHA 并提示错误。

## GitHub API 与网络错误

- 使用公共 GitHub API；不要求用户提供 token。
- 尊重 API rate-limit 响应，显示下次可重试时间，不把失败伪装成“已是最新版”。
- 设置请求超时、最大文件数、最大单文件大小和最大总下载量。
- 下载只接受 GitHub API/Raw GitHub 的 HTTPS 地址，禁止重定向到非允许主机。
- SHA、路径和清单验证失败时终止整个更新。

## 用户体验

- 无更新时不弹窗。
- 下载时只在设置/状态区域显示低干扰进度。
- 下载完成且正在对局：显示“更新已就绪，将在本局结束后应用”。
- 安全状态：自动刷新当前窗口，不退出 Electron。
- 外壳变化：显示“此更新需要新版安装包”，提供发行页入口；不循环提示同一 SHA。
- 失败：保留旧版本并显示可重试的明确错误。

## 测试

单元测试：

- compare 路径分类与未知路径的保守处理。
- Git blob SHA 计算、清单差异和删除项。
- 路径穿越、绝对路径、符号链接及非允许主机拒绝。
- 状态机：无更新、下载、等待安全、应用、回滚、需要安装包、失败。

集成测试：

- 用临时目录模拟内置版本、更新版本和指针切换。
- 下载中断不会改变当前版本。
- 校验失败不会应用部分内容。
- 对局状态下不刷新，安全状态事件到达后只刷新一次。
- 新版本启动握手失败时恢复上一版本。

验收：

- 安装版启动后可发现 `main` 新提交。
- 只改游戏内容时后台下载，当前对局不中断，对局结束后窗口自动刷新并加载新提交。
- 改 Electron/依赖时不覆盖，明确提示安装新版。
- 断网、GitHub 限流、磁盘不足或损坏下载均不破坏可运行版本。
